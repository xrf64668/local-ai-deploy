# 04 · 下载模型前先核对版本

**目标：** 不盲目下载几十 GB，也不把不完整或错误格式的权重当作可用模型。

## 第一步：找到可信的模型来源

优先使用模型开发者的官方发布仓库或有明确来源的转换仓库，并检查：

1. 模型名称、变体、基础模型与转换来源。
2. 权重格式（GGUF / MLX / safetensors 等）和量化精度。
3. 所需运行时版本与加载入口。
4. 文本编码器、VAE、tokenizer 等是否需要单独下载。
5. 许可证和是否允许你计划中的使用方式。

## 第二步：记录固定版本

Hugging Face 仓库通常可通过 Commit SHA 锁定 revision。示例：

```text
模型：LTX-2.5（具体 MLX 转换仓库）
仓库：<owner/repo>
revision：<准确 commit SHA>
runtime：<运行时 Git Commit>
量化：Q4
文件清单：<由实际仓库获取>
```

以上是记录模板，不是下载指令。**不要把仓库最新的文件布局硬编码成所有历史版本都适用。**

## 第三步：下载前确认空间

磁盘需求不止是模型权重，还包括下载临时文件、缓存、文本编码器、VAE 和输出视频。先执行：

```bash
df -h .
```

然后计算预计下载总量并留出足够余量。下载中断时优先重试，不要自动删除已通过验证的旧权重。

## 第四步：下载后按模型仓库核对

- 文件数目和文件大小是否符合上游该 revision 的清单。
- 如有可信上游 SHA-256，逐一核对；只有本地 SHA 不等同于上游认证。
- 不要因为缺少 `config.json` 就自行创建假配置：不同推理引擎使用的配置布局可能不同。
- 在进入下一阶段前，仍然不能宣称已可推理。
