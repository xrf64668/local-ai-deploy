# 新手部署教程维护规范

本站定位为「第一次接触本地 AI，也能跟随步骤完成验证」的开源中文教程。

## 新手可读性优先原则

- 默认读者不认识 Git、pip、venv、MPS 和 CUDA；术语首次出现时要给一句人话解释。
- 有 Desktop / 图形路线时，**把零命令入门放在最前面**；手动安装、API、服务器和高级依赖放在独立进阶页。
- 安装命令按目的拆开；**一个步骤只解决一个问题**，必须说明用途、在哪里执行、期望输出、失败时下一步。
- 不向新手展示一整屏未知的 `export`、`pip`、`git clone` 命令而不解释。
- 普通用户先让软件跑起来，再解释虚拟环境和缓存，不要求所有读者提前学习专业架构。
- 新手教程至少有一次“成功打开软件”和一次“真实生成文件”的验收，并清楚区分。
- 对不同系统/安装方式分路线，避免把 Mac MPS 和 NVIDIA CUDA、Desktop 和 Manual 的步骤混在一起。

## 内容最小验收标准

每篇部署教程至少有这七个章节：

1. **适用范围**：操作系统、CPU/GPU、软件版本、运行时（MPS / MLX / CUDA / CPU）。
2. **前置检查**：用可复制的指令查看现状，不直接改动用户系统。
3. **安装过程**：区分用户实际要执行的命令、示例输出、可选步骤。
4. **每步验收**：明确什么输出算通过，什么报错应停止。
5. **真实推理**：不能把服务启动成功描述成模型生成成功。
6. **API/自动化**：展示认证边界、任务状态和失败处理。
7. **排障与回滚**：对影响较大的操作写出恢复方法。

## 版本与证据

- 标注文档核验日期、系统版本、GPU 型号、模型权重或量化版本、推理后端。
- 「本站作者亲自验证」「社区验证」「官方文档参考」「理论适配」分开表述。
- 模型内存/显存阈值仅作为初筛，不声称是官方最低要求。
- 每次外部依赖大版本更新时重新检查命令和链接。
- 不把未经验证的运行结果、速度或帧数写成真实测试数据。

## 安全与工程规范

- 不使用未经解释的 `curl | bash` 安装命令。
- 不建议将没有鉴权的 API 服务监听公网地址。
- 独立项目里的虚拟环境、模型、缓存及输出，应在用户指定的项目根目录内，不污染其他模型项目。
- 不将 token、密钥、个人路径或设备敏感信息提交到 Git。
- 每次发布执行 `npm ci` 和 `npm run docs:build`；检查页面中的相对链接与版本号。

## 更新流程

本站的内容变更优先在 GitHub 上维护。修改前检查现有 `main`，生成新内容，构建成功后提交；若构建失败则先修复，不应描述为已经上线。
