# Mac · Wan2.2 TI2V-5B MLX 方案

**状态：实验性 / 待目标机器完成真实生成验证。** 不能因为模型权重成功下载，或 LTX 已运行，就把 Wan 标为已成功部署。

## 核对四个兼容条件

| 项目 | 需要确定 |
| --- | --- |
| 模型权重 | 具体 Wan2.2 TI2V-5B 的 MLX 转换仓库、量化精度 |
| 推理运行时 | 明确支持该转换权重的 `mlx-video` 版本 |
| 组件 | 模型配置、文本编码器、VAE 及分词器的真实布局 |
| 机器 | Apple Silicon、统一内存、空闲磁盘与内存压力 |

参考：[Wan2.2 原始项目](https://github.com/Wan-Video/Wan2.2) 及 [mlx-video](https://github.com/Blaizzy/mlx-video)。原始 PyTorch 权重不能假定直接适配 MLX。

## 最小验证策略

1. 先进入 [01 · 硬件预检](/mac/01-preflight/) 确认运行空间。
2. 为 Wan 创建**独立** Python 环境，记录依赖与运行时代码的 Commit。
3. 按特定模型 revision 的文件清单下载权重，不补造缺失的配置文件。
4. 首次只尝试短片、低分辨率与单并发（例如约 512×320、17 帧的实验参数），具体参数仍以所用加载器为准。
5. 检查模型加载日志、输出文件、视频时长和播放情况。
6. 保存测试结果，失败也要记录原因。

::: warning 资源门槛是估算而非承诺
32GB 统一内存只能作为某些量化/低负载方案的**实验起点**；不能把它写成官方最低需求或保证兼容。帧数、注意力实现、文本编码器和 VAE 都会影响峰值内存。
:::

## 常见错误

- 模型目录/配置格式与运行时不一致。
- 文本编码器或 VAE 没有按所选 revision 配套准备。
- Metal 内存不足，或多个模型同时运行。
- 运行时升级后接口、参数名称变化。
