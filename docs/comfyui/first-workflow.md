# ComfyUI · 生成第一张图片

本页适合刚完成 [Mac](/comfyui/mac/)、[Ubuntu](/comfyui/ubuntu/) 或 [Windows](/comfyui/windows/) 安装的用户。**目标不是只打开界面，而是实际生成一张可打开的图片。**

## 01 · 检查准备状态

- [ ] 已经打开 ComfyUI 编辑器，启动日志没有致命错误
- [ ] 已确认本次使用的 GPU / MPS / CPU 后端
- [ ] 已知道 ComfyUI 的模型目录在哪里
- [ ] 磁盘上有足够空间放置模型与结果

## 02 · 选择最简单的本地工作流

打开 ComfyUI 的工作流模板入口，选择**支持当前机器的本地 Text to Image 工作流**。不要把需要云端登录/付费的 Partner API 节点当成本地部署测试。

::: tip 为什么不写死某个模型直链？
模型权重、模板和节点版本会更新。先根据官方模板要求找到精确模型版本，能减少“文件下载了却跑不起来”的情况。
:::

## 03 · 找到并下载缺失的模型

如果画布提示找不到模型，把缺失文件的**完整名称**记录下来，去发布方提供的模型仓库查找。

根据工作流提示分别放入 Checkpoints / Diffusion Models / VAE / LoRA / Text Encoders 等对应目录。不同模型不一定使用同一组组件。

[详细了解模型目录](/comfyui/models-and-paths/)

## 04 · 先运行低负载参数

如果工作流与模型允许，可以先从 512×512、单张输出开始；其他参数沿用官方模板值。暂时关闭高分辨率增强、多 LoRA、批量任务。

点击 Queue / Run，等待队列执行。Mac 使用 MPS 的表现可能和 NVIDIA CUDA 不同，不能仅凭生成速度判断安装是否正确。

## 05 · 判断成功

- 工作流无红色错误节点；
- 能在预览看到结果；
- 输出目录产生一个实际文件；
- 用图片查看器打开文件正常；
- 记录模型、工作流版本、分辨率、步数和运行时间。

::: warning 还没有生成文件？
检查队列、节点和日志。服务启动和模型加载只是前置条件，不能替代真正生成。
:::

## 06 · 下一步做什么

完成首次生成后，再开始尝试 [ComfyUI API](/comfyui/api/)；它需要从已跑通的工作流导出 API 格式 JSON。遇到问题先看 [排错清单](/comfyui/troubleshooting/)。
