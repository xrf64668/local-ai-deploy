# Mac 的 01–07 部署路线

这一套阶段主要用于帮助新手理解，也可以作为长期部署工具的架构标准。**它不是断言你的电脑已经安装好了全部模型。**

## 7 个阶段的产物

| 阶段 | 输入 | 产物 | 失败时 |
| --- | --- | --- | --- |
| 01 硬件预检 | Mac 机器 | 环境报告 | 停止不兼容安装 |
| 02 独立环境 | 目标项目目录 | 独立 Python 环境、缓存 | 保留已有模型 |
| 03 运行时 | 模型类别 | 版本固定的推理后端 | 不影响其他后端 |
| 04 模型下载 | 模型仓库与 revision | 版本锁定的权重 | 不覆盖已验证版本 |
| 05 验证 | 权重 + 后端 | 可加载及最小推理记录 | 保存日志和失败原因 |
| 06 推理 | 参数与资源预算 | 可打开的图片 / 音视频 | 标记任务失败 |
| 07 API | 通过验证的后端 | HTTP 调用或任务队列 | 返回明确错误状态 |

建议的模型状态：`REGISTERED → DOWNLOADED → VALIDATED → LOADABLE → READY`。其中 READY 必须经过真实推理验证，不能只依靠文件数量判断。

## 为什么各模型要隔离？

MLX 语言模型、LTX 的视频加载器、Wan 转换权重和 ComfyUI/PyTorch MPS 使用的依赖及模型布局可能不同。混装在同一个 Python 虚拟环境中会引入版本冲突。

### 推荐目录示意

```text
CUSTOM_DEPLOY/
├── 01_*.sh ... 07_*.sh   # 具体名称以你的部署项目为准
├── .envs/                # 每种模型/运行时独立环境
├── cache/                # pip / HF / uv / 临时文件
├── models/               # 下载的权重、快照
├── repos/                # 推理框架代码及版本
├── outputs/              # 实际生成结果
├── logs/                 # 错误日志
├── config/               # 私有配置，不提交凭据
└── api/                  # 可选的 API 服务
```

当脚本与其资源处于同一项目目录时，采用自身位置推导路径：

```bash
SCRIPT_DIR="$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd -P)"
PROJECT_ROOT="$SCRIPT_DIR"
```

如果脚本放在子目录，应该基于实际层级确定根目录；不要假设所有脚本的父目录都一样。

## 运行约束

- 默认无 `sudo`，不自动安装到全局 Python；需要系统工具时给出明确说明。
- 模型、缓存、输出优先放在当前部署项目中。
- 不强行重装已经通过验收的 LTX Python 环境。
- 视频生成优先单任务执行，根据设备内存决定并发和分辨率。
- API 默认绑定 `127.0.0.1`，需要远程访问时使用受保护的通道。
