# 06 · 本地推理与性能边界

**目标：** 生成结果可复现、出错可定位，不靠反复试错让系统内存耗尽。

## 推理的四项成本

- **磁盘**：模型、缓存与结果文件。
- **加载**：模型权重解码、MLX / Metal 内存分配。
- **生成**：分辨率、帧数、步数、模型中间激活。
- **输出**：VAE 解码、视频编码和输出文件写入。

## 视频模型从低负载开始

对于 M4/32GB 统一内存的 LTX-2.5 Q4，已有低负载实践基线采用约 `512×320`、25 model frames 的短任务。这是**特定配置下的测试边界**，不是所有 Mac 都能运行的推荐画质。

Wan2.2 Q8 必须重新验证；不能因为同是 MLX 或 32GB 就复用 LTX 的成功结论。

## 运行时要观察什么

```bash
memory_pressure -Q
df -h .
```

再结合推理进程输出、模型日志以及生成文件核对。Mac 没有 NVIDIA 的 `nvidia-smi`；不要照搬 CUDA 指令。

## 视频任务队列建议

视频生成通常耗时，应以独立任务运行：`queued → running → completed / failed / canceled`。对于统一内存较紧张的机器，先将 GPU 任务并发设为 1，再根据真实测试逐步放开。

任务记录应包含：所用模型、版本、输入摘要、帧数、尺寸、步数、执行耗时、错误码和输出文件。

**成功标志：** 用可复现的命令生成了实际文件，且输出媒体可解码。
